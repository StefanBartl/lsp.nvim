1. INTRODUCTION                                      *lspdoctor-introduction*

LSP Doctor is a comprehensive diagnostic and health checking system for
Neovim's built-in LSP client. It provides multiple inspection modes to help
you understand and debug LSP configuration issues.

Key capabilities:
  • Health checks for server status and configuration
  • Debug info for configuration layers
  • Quick and deep inspection modes
  • Combined reports with all information

==============================================================================
2. FEATURES                                              *lspdoctor-features*

  • Health Check: Verify server status, configuration, and errors
  • Debug Mode: Inspect registry, configs, and completion candidates
  • Quick Mode: Fast overview of clients and diagnostics
  • Deep Mode: Detailed capabilities and workspace analysis
  • All Mode: Combined comprehensive report
  • Scratch Buffer: View reports in dedicated buffer with keymaps
  • Flexible Output: Print, notify, or scratch buffer rendering

3. SETUP                                                    *lspdoctor-setup*

                                                            *lspdoctor.setup()*
lspdoctor.setup({opts})
    Configure LSP Doctor behavior.

    Parameters: ~
        {opts}  (table|nil)  Configuration options

    Options: ~
        use_notify              (boolean)  Use vim.notify instead of print
                                           Default: false
        auto_open_scratch       (boolean)  Auto-open scratch for long output
                                           Default: false
        scratch_threshold       (number)   Lines before auto-scratch
                                           Default: 20
        list_limit              (number)   Max items in quick mode lists
                                           Default: 10
        show_capabilities       (boolean)  Show detailed capabilities
                                           Default: true
        show_workspace          (boolean)  Show workspace folders
                                           Default: true
        show_tools              (boolean)  Check external tools
                                           Default: true
        show_conflicts          (boolean)  Detect provider conflicts
                                           Default: true
        formatter_priority      (table)    Formatter preference order
                                           Default: {}
        semantic_tokens_timeout (number)   Semantic tokens probe timeout (ms)
                                           Default: 300
        scratch_filetype        (string)   Filetype for scratch buffer
                                           Default: "markdown"

    Example: >lua
        require('lsp.lspdoctor').setup({
          use_notify = false,
          auto_open_scratch = true,
          formatter_priority = { "null-ls", "eslint", "lua_ls" },
        })
<

4. COMMANDS                                              *lspdoctor-commands*

                                                                  *:LspDoctor*
:LspDoctor [mode]
    Run LSP Doctor diagnostics.

    Modes:
        (none)  All modes combined (default)
        health  Server health check
        debug   Configuration debugging
        quick   Quick overview
        deep    Detailed inspection
        all     Explicit combined mode

    Bang variant:
        :LspDoctor!  Open output in scratch buffer instead of printing

    Examples: >vim
        :LspDoctor              " All modes, print output
        :LspDoctor! health      " Health check in scratch buffer
        :LspDoctor debug        " Debug info, print output
        :LspDoctor! deep        " Deep inspection in scratch buffer
<

5. API                                                        *lspdoctor-api*

                                                           *lspdoctor.health()*
lspdoctor.health({bufnr}, {use_scratch})
    Run health check for LSP servers.

    Parameters: ~
        {bufnr}        (number|nil)   Buffer number (0 for current)
        {use_scratch}  (boolean|nil)  Open in scratch buffer

    Returns: ~
        {results}  (table)  Array of server health status

    Example: >lua
        local results = require('lsp.lspdoctor').health(0)
        for _, r in ipairs(results) do
          print(r.name, r.running, r.config_exists)
        end
<

                                                            *lspdoctor.debug()*
lspdoctor.debug({bufnr}, {use_scratch})
    Run debug info for configuration layers.

    Parameters: ~
        {bufnr}        (number|nil)   Buffer number (0 for current)

    Returns: ~

    Example: >lua

6. MODES                                                    *lspdoctor-modes*

HEALTH MODE                                              *lspdoctor-mode-health*

    Checks each expected LSP server for:
      • Running status (✅/❌)
      • Configuration existence
      • Start attempts and errors
      • Actionable diagnostics

    Use when:
      • "Why isn't my LSP working?"
      • Verifying server status after changes

DEBUG MODE                                                *lspdoctor-mode-debug*

    Inspects configuration layers:
      1. Expected servers (filetype mapping)
      2. Configured servers (registry.ACTIVE)
      3. Registered configs (vim.lsp.config)
      4. Running clients (active connections)
      5. Completion candidates (:LspStart suggestions)

    Use when:
      • "Why doesn't :LspStart show my server?"
      • Finding configuration gaps
      • Debugging registration issues

QUICK MODE                                                *lspdoctor-mode-quick*

    Fast overview of:
      • Attached clients
      • Diagnostic counts
      • Provider conflicts
      • Offset encoding mismatches
      • Formatter policy

    Use when:
      • Quick status check
      • Verifying basic LSP state

DEEP MODE                                                  *lspdoctor-mode-deep*

    Everything from quick mode plus:
      • Workspace folders and root_dir
      • Detailed capabilities per client
      • CodeLens & InlayHints status
      • Semantic tokens probe
      • External tools check
      • Optional integrations

    Use when:
      • "What capabilities does this server have?"
      • Debugging specific LSP features
      • Workspace configuration issues

ALL MODE                                                    *lspdoctor-mode-all*

    Combines health + debug + deep in one report.

    Use when:
      • You want everything at once
      • Creating diagnostic reports

8. TROUBLESHOOTING                                  *lspdoctor-troubleshooting*

NO SERVERS IN HEALTH CHECK ~

    Symptoms:
      • "No LSP servers configured for this buffer"
      • Empty health check results

    Diagnosis: >vim
        :LspDoctor debug
<
    Look at:
      • Section 1: Expected servers for filetype
      • Section 2: Configured servers (registry.ACTIVE)
      • Section 3: Registered configs (vim.lsp.config)

    Common causes:
      • Filetype not mapped in configuration
      • Registry not initialized
      • Configs not registered via config.add()

CONFIG EXISTS BUT WON'T START ~

    Symptoms:
      • Config exists: ✅
      • Running: ❌
      • Start attempts: > 0

    Diagnosis:
      1. Check LSP log: >vim
            :LspLog
<
      2. Verify binary exists: >bash
            which <server_name>
<
      3. Test manual start: >lua
            vim.lsp.start({
              name = "server_name",
              cmd = { "server_name" },
              root_dir = vim.fn.getcwd()
            })
<

OFFSET ENCODING MISMATCH ~

    Symptoms:
      • Warning about utf-8 vs utf-16
      • Positioning issues in rare cases

    Usually safe to ignore. If problems persist:
      1. Check server documentation for encoding configuration
      2. Configure all servers to use same encoding
      3. Restart affected clients

SCRATCH BUFFER NOT OPENING ~

    Symptoms:
      • Output printed despite :LspDoctor!
      • auto_open_scratch not working

    Check:
      • Output length < scratch_threshold
      • Verify configuration: >lua
            :lua print(vim.inspect(require('lsp.lspdoctor').config))
<
